### 2.1 Follow-up — the gradient really has to follow the theme

The first version's thumb was _correct_ on paper (tokens in the palette, the
same `theme` object as the board and tray, inline JSX — no stale memo), yet on
device the pill kept the previous theme's fill while everything around it
repainted. The one node that behaved differently is Skia's: the `LinearGradient`
is a **shared paint leaf**, and RN Skia can keep the previous paint when only
the _contents_ of the `colors` array change between identical renders. The board
and shelf repaint because their shapes carry live `color` props.

Fix (`puzzle-board.tsx`, commit `4e4416d`): the thumb's `<LinearGradient>` is
now **keyed by `theme.id`**, so React destroys and recreates the shader node on
every theme switch. That deterministically rebuilds the paint →

- MEADOW renders `#A4FF7D → #0A8B24`
- WOOD renders `#C19A6C → #BA8A65`

…LEFT→RIGHT in the thumb's own local coordinates, without restarting or
rebuilding the component. The existing theme-token `color` prop stays as a flat
fallback. Nothing else in the scrollbar changed.

## 3. Design notes

- The gradient lives entirely in the palette layer, keeping
  `themes.test.ts`'s no-hardcoded-hex rule intact (component source only sees
  theme tokens and `rgba(...)`).
- The thumb's gradient coordinates are fixed in the group's local space rather
  than the canvas, so sliding the pill never skews the gradient direction or
  hops its stops.
- One `BOARD_FRAME_PAD` value does the work of a per-grid layout pass; the
  scrollbar's outer-reach hit areas and the tray shelf simply land 8pt inside
  the shell on every device and density.

## 6. Debug-session follow-up — invisible thumb: a TDZ `vw` capture

A later session on the live debug build (ci-26, expo-dev-client 6×6 grid) found
the gradient thumb was **entirely absent for both themes** — switching to Wood
did not make it tan, so the theme-key fix (2.1) and the tokens were fine and the
render path itself was broken.

### 6.1 Root cause

In `puzzle-board.tsx` the slider geometry block (~1622-1648) builds the
`trayThumbX` worklet **before** `const { vw, ... } = layout` is destructured
lower in the component (~1699). The worklet's `trackInnerEnd` line referenced
bare `vw`, so Reanimated snapshotted `undefined` (TDZ) when the worklet was
created → `trayThumbX.value` stayed `null` → `trayThumbTransform =
[{ translateX: null }]` → the pill's transformed Group never painted. The track
and arrow buttons rendered because they sit in JSX below the destructure; the
drag gesture memo (line ~1300) destructures its own `vw` at line ~1307, so its
math was never affected.

**Fix (one line, not committed):** `puzzle-board.tsx:1645`
`trackInnerEnd = layout.vw - TRAY_PAD - FX.tray.sliderArrowW - trayThumbW`.

### 6.2 On-device verification (Wood → Meadow, live over adb)

After the fix the pill renders as an opaque capsule in the slider band at the
tray bottom (6×6; x≈190-580, y≈2550-2663 on this device). Pixel forensics of
the ramp, left→right:

- **MEADOW**: `(162,253,124) → (18,145,41)` ≈ `#A4FF7D → #0A8B24`
- **WOOD**: `(193,154,108) → (186,138,101)` = `#C19A6C → #BA8A65` (exact)

Screenshots saved: `meadow-pill-6x6.png`, `wood-pill-6x6.png` (see also the
byte-diff `git diff` = exactly the one line above; no probes/JUNK left).

### 6.3 Drag/scroll — not machine-verifiable in this debug build

The pill's dragging (pan mode 4) and the arrow taps drive the same
`trayScroll → trayThumbX` derivation the fix restored, but the dev-client
canvas **rejected every injected touch** — pill-drag, arrows, camera-pan and
piece-grab all changed zero canvas pixels while plain RN buttons (Pause) kept
working. Confirmed across several clean reloads and a full Metro restart
(`npx expo start --dev-client`; adb reverse kept). A temporary
`runOnJS(console.log)` worklet probe threw in this Reanimated version
(`[Worklets] Locally defined function passed to scheduleOnRN (log)`) and wedged
a dev-client error sheet that swallowed touches — reverted; the file is clean.
Worth a 30-second human check: drag the pill / tap an arrow on the 6×6 and
watch the tray scroll.
